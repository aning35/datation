# 数据看板设计标准作业程序  
# Dashboard Design SOP

## 1. 技能定位

本技能用于设计面向业务决策、运营监控、风险预警、经营分析、数据治理、预测结果展示和管理驾驶舱的数据看板。

本技能主要回答：

- 这个看板应该给谁看？
- 看板要支持什么业务决策？
- 应该展示哪些核心指标？
- 指标如何分层？
- 页面如何布局？
- 哪些数据适合用什么图表？
- 用户应该如何筛选、下钻和联动？
- 异常和风险如何预警？
- 数据口径和更新时间如何说明？
- 看板如何验收、上线和持续迭代？

本技能强调：

- 先业务场景，后页面设计；
- 先用户角色，后指标展示；
- 先决策问题，后图表选择；
- 先指标体系，后视觉布局；
- 先信息层级，后视觉美化；
- 先口径可信，后展示炫酷；
- 先可行动，后可观看；
- 不把看板做成图表堆砌；
- 不用视觉特效掩盖数据口径问题。

## 4. 边界与防越界声明

### 4.1 本技能不是单纯 UI 美化

数据看板设计不是“把图表做漂亮”。

看板必须服务：

- 决策；
- 监控；
- 诊断；
- 预警；
- 复盘；
- 行动。

如果一个看板只是视觉复杂，但用户看完不知道问题在哪里、该做什么、谁负责处理，则不是合格看板。

---

### 4.2 本技能不是指标治理

如果用户的问题是：

- 指标口径不统一；
- 指标血缘不清；
- 指标 owner 不明确；
- 数据质量不稳定；
- 指标字典缺失；

应衔接 `data-governance`。

本技能可以要求明确指标口径，但不替代完整数据治理。

---

### 4.3 本技能不是数据分析

如果用户需要回答：

- 为什么指标下降；
- 哪些维度贡献最大；
- 哪些群体表现异常；
- 数据背后的洞察是什么；

应衔接 `data-analysis`。

本技能负责把分析结果设计成可视化和可操作看板。

---

### 4.4 本技能不是预测建模

如果用户需要预测未来销售额、订单量、风险率、库存需求，应衔接 `forecasting`。

本技能可以设计预测结果展示模块，但不负责预测模型本身。

---

### 4.5 本技能不是风险模型

如果用户需要建立风险识别、风险评分、KRI 预警规则，应衔接 `risk-analysis`。

本技能负责将风险指标、风险等级、预警事件和处置状态设计为看板。

## 5. 核心执行原则

1. **先场景，后图表**  
   不知道业务场景时，不得直接堆图表。

2. **先角色，后信息**  
   老板、运营、销售、风控、数据团队需要看的内容不同。

3. **先问题，后指标**  
   每个指标都应回答一个具体业务问题。

4. **先总览，后下钻**  
   页面应先展示整体健康度，再支持用户定位问题。

5. **先异常，后明细**  
   用户最需要优先看到风险、异常和待处理事项。

6. **先口径，后展示**  
   指标口径不清时，不应直接上线看板。

7. **先行动，后观察**  
   看板不仅要告诉用户“发生了什么”，还要提示“下一步做什么”。

8. **先简洁，后丰富**  
   默认页面只展示高价值信息，复杂信息放到下钻和明细中。

9. **先对比，后孤立数值**  
   单个数字价值有限，应提供同比、环比、目标值、行业基准或历史区间。

10. **先可用，后炫酷**  
   看板应优先保证可读性、准确性、性能和可解释性。

## 6. 任务分级与流程适配

### Tier 1：单页轻量看板

适用场景：

- 单一业务场景；
- 指标较少；
- 只需要一页看板；
- 用于快速查看现状；
- 不需要复杂权限和下钻。

典型问题：

- “帮我设计一个销售数据看板。”
- “帮我设计一个日报看板。”
- “帮我设计一个项目进度看板。”
- “帮我设计一个风险预警单页。”

执行流程：

> 步骤 1 → 步骤 2 → 步骤 3 → 步骤 4 → 步骤 8

重点输出：

- 页面结构；
- 核心指标；
- 图表布局；
- 筛选条件；
- 简单预警。

---

### Tier 2：标准业务分析看板

适用场景：

- 多指标；
- 多维度；
- 多模块；
- 需要总览、分析、明细；
- 需要支持业务诊断；
- 需要上线给团队长期使用。

典型问题：

- “帮我设计用户增长看板。”
- “帮我设计经营分析 dashboard。”
- “帮我设计保险业务数据看板。”
- “帮我设计风险监控看板。”
- “帮我设计数据质量看板。”

执行流程：

> 步骤 1 → 步骤 2 → 步骤 3 → 步骤 4 → 步骤 5 → 步骤 6 → 步骤 7 → 步骤 8 → 步骤 9

重点输出：

- 用户角色；
- 指标体系；
- 页面信息架构；
- 图表方案；
- 交互逻辑；
- 预警机制；
- 数据口径；
- 权限设计；
- 验收标准。

---

### Tier 3：企业级经营驾驶舱 / 数据产品

适用场景：

- 企业级管理驾驶舱；
- 多业务线看板体系；
- 多角色门户；
- 指标体系复杂；
- 需要权限、订阅、告警、任务闭环；
- 需要支持 AI 问数或自动洞察；
- 需要平台化复用。

典型问题：

- “帮我设计企业经营驾驶舱。”
- “帮我设计一套数据看板产品。”
- “帮我设计 AI 数据问答返回的可编辑看板。”
- “帮我设计集团级经营分析平台。”
- “帮我设计风险预警中心和处置闭环。”

执行流程：

> 完整执行步骤 1 - 12，并建立页面体系、指标治理、权限体系、组件规范、告警机制和迭代机制。

重点输出：

- 看板体系架构；
- 角色权限模型；
- 指标地图；
- 页面模板；
- 组件规范；
- 交互规范；
- 预警体系；
- 数据服务要求；
- 上线验收；
- 运营机制。

## 7. 标准工作流

## 步骤 1：看板目标与用户定义

### 1.1 明确看板目标

看板目标必须具体。

常见目标：

- 经营总览；
- 业务监控；
- 异常预警；
- 指标诊断；
- 销售管理；
- 客户运营；
- 用户增长；
- 风险处置；
- 数据质量监控；
- 项目进度管理；
- 预测结果查看；
- 管理层决策支持。

错误目标：

```text
做一个好看的数据大屏。
```

正确目标：

```text
为销售负责人提供每日销售目标达成、渠道转化、区域业绩、重点客户跟进和异常预警，支持其快速发现问题并安排销售动作。
```

---

### 1.2 明确用户角色

必须明确谁使用看板。

常见角色：

- CEO / 总经理；
- 业务负责人；
- 销售负责人；
- 运营负责人；
- 风控负责人；
- 财务负责人；
- 产品经理；
- 数据分析师；
- 一线销售；
- 客服主管；
- 项目经理；
- 安全管理人员；
- 数据治理人员。

不同角色关注点不同。

示例：

| 角色 | 关注点 |
|---|---|
| CEO | 经营结果、增长趋势、风险预警、战略目标达成 |
| 销售负责人 | 销售额、线索、商机、成交率、区域排名、销售动作 |
| 运营负责人 | 流量、转化、留存、活动效果、用户分层 |
| 风控负责人 | 风险等级、预警事件、处置进度、高风险对象 |
| 数据负责人 | 数据质量、任务延迟、指标口径、数据血缘 |

---

### 1.3 明确使用频率

看板使用频率影响设计。

| 使用频率 | 设计重点 |
|---|---|
| 实时 | 监控、告警、异常突出 |
| 每日 | 目标达成、昨日变化、待办动作 |
| 每周 | 趋势、复盘、重点问题 |
| 每月 | 经营分析、目标复盘、策略调整 |
| 季度 | 管理汇报、战略评估 |
| 临时分析 | 灵活筛选、下钻、导出 |

---

### 1.4 明确使用终端

不同终端设计不同：

- PC 后台；
- 大屏驾驶舱；
- 平板；
- 移动端；
- 邮件日报；
- 企业微信 / 飞书卡片；
- AI 对话返回结果；
- 嵌入式业务系统页面。

大屏适合展示总览和趋势，不适合复杂操作。  
PC 适合分析和下钻。  
移动端适合查看预警和待办。

---

## 步骤 2：业务问题与指标体系设计

### 2.1 明确业务问题

每个看板模块都应回答一个问题。

示例：

| 业务问题 | 对应模块 |
|---|---|
| 当前整体经营是否健康？ | 核心指标总览 |
| 哪些指标异常？ | 异常预警模块 |
| 哪些渠道贡献最大？ | 渠道分析模块 |
| 哪些地区表现落后？ | 地域分析模块 |
| 哪些客户需要跟进？ | 客户明细模块 |
| 哪些风险未处理？ | 风险处置模块 |

---

### 2.2 指标分层

推荐分为：

#### L0：北极星指标

反映最终业务目标。

例如：

- GMV；
- 净收入；
- 利润；
- 活跃客户数；
- 续费收入；
- 风险调整后收益；
- 安全事故率。

#### L1：结果指标

反映业务结果。

例如：

- 销售额；
- 订单量；
- 成交客户数；
- 留存率；
- 赔付率；
- 投诉率；
- 目标达成率。

#### L2：过程指标

反映业务过程。

例如：

- 曝光量；
- 点击量；
- 线索数；
- 商机数；
- 报价数；
- 支付成功率；
- 处理时效。

#### L3：诊断指标

用于定位问题。

例如：

- 渠道转化率；
- 区域销售额；
- 版本崩溃率；
- 客户分层贡献；
- 医院异常赔付率；
- 供应商延期率。

#### L4：行动指标

用于驱动业务动作。

例如：

- 待跟进客户数；
- 逾期未处理工单数；
- 高风险预警数；
- 超期整改隐患数；
- 库存预警 SKU 数。

---

### 2.3 指标卡设计

核心指标卡应包含：

- 指标名称；
- 当前值；
- 单位；
- 同比；
- 环比；
- 目标值；
- 目标达成率；
- 趋势箭头；
- 状态颜色；
- 口径说明入口。

示例：

```text
销售额
当前值：1,280 万
环比：+12.5%
同比：+8.2%
目标达成率：76%
状态：正常
```

---

### 2.4 指标口径要求

每个核心指标必须明确：

- 指标定义；
- 计算公式；
- 时间口径；
- 统计粒度；
- 过滤条件；
- 去重规则；
- 数据来源；
- 更新时间；
- owner。

指标口径不清时，看板不得上线为正式版本。

---

## 步骤 3：页面信息架构设计

### 3.1 总体布局原则

推荐从上到下：

1. 全局筛选区；
2. 核心指标总览；
3. 关键趋势与目标达成；
4. 维度拆解；
5. 异常预警；
6. 重点对象；
7. 明细表；
8. 口径说明与更新时间。

---

### 3.2 页面结构模板

```text
页面顶部：
- 看板名称
- 更新时间
- 数据状态
- 全局筛选器
- 导出 / 订阅 / 口径说明

第一屏：
- 核心 KPI 卡片
- 目标达成情况
- 总体趋势
- 异常预警摘要

第二屏：
- 关键维度拆解
- 渠道 / 区域 / 产品 / 客户分析
- 排名和贡献度

第三屏：
- 风险、异常、待办事项
- 高风险对象列表
- 处置状态

第四屏：
- 明细数据表
- 下钻入口
- 操作记录
```

---

### 3.3 总览页设计

总览页应回答：

- 现在整体情况如何；
- 和目标相比怎么样；
- 和上期相比怎么样；
- 有没有异常；
- 哪些模块需要关注；
- 下一步要去哪看。

总览页不宜放太多明细，重点是快速判断。

---

### 3.4 分析页设计

分析页应支持：

- 趋势分析；
- 维度对比；
- 贡献度拆解；
- 分群对比；
- 漏斗分析；
- 留存分析；
- 地域分析；
- 排名分析；
- 明细下钻。

---

### 3.5 明细页设计

明细页用于行动。

应包含：

- 明细对象；
- 关键字段；
- 风险状态；
- 处理状态；
- owner；
- 操作入口；
- 备注；
- 历史记录；
- 导出能力。

明细页不是简单表格，应支持业务处理。

---

## 步骤 4：图表选择规范

### 4.1 指标卡

适合展示：

- 总收入；
- 订单量；
- 客户数；
- 转化率；
- 风险数；
- 目标达成率；
- 今日新增；
- 待处理事项。

适用位置：

- 页面顶部；

## 步骤 6：预警与异常设计

### 6.1 预警类型

常见预警：

- 指标低于目标；
- 指标超过阈值；
- 同比异常；
- 环比异常；
- 超出历史波动区间；
- 数据延迟；
- 数据质量异常；
- 高风险对象新增；
- 待办事项超期；
- 预测偏离实际。

---

### 6.2 预警等级

推荐分为：

| 等级 | 含义 | 展示方式 | 动作 |
|---|---|---|---|
| 正常 | 无明显异常 | 默认状态 | 无需处理 |
| 提醒 | 轻微波动 | 弱提示 | 观察 |
| 警告 | 明显异常 | 黄色/橙色提示 | 责任人关注 |
| 严重 | 高风险 | 红色提示 | 立即处理 |
| 阻断 | 影响决策 | 强提示/置顶 | 暂停使用或升级处理 |

---

### 6.3 异常解释

异常提示不应只显示“异常”，还应说明：

- 哪个指标异常；
- 异常发生时间；
- 偏离程度；
- 对比基准；
- 影响范围；
- 可能相关维度；
- 建议查看路径；
- 建议处理动作。

示例：

```text
转化率异常下降：
当前转化率 3.2%，低于近 30 日均值 4.8%，偏离 -33%。
异常主要集中在安卓 3.8.1 版本新用户。
建议查看：版本转化漏斗 → 安卓新用户明细。
```

---

### 6.4 待办闭环

如果看板用于风险、运营、项目或质量管理，应支持：

- 生成待办；
- 指派 owner；
- 设置截止时间；
- 记录处理动作；
- 处理状态流转；
- 关闭确认；
- 复盘记录。

- 客户名称；
- 企业敏感信息；
- 合同金额；

- 个人隐私信息。

看板设计时必须考虑：

- 是否展示明细；

- 是否允许导出；

### 8.1 数据口径说明

看板必须提供口径入口。

包括：

- 计算公式；
- 统计周期；
- 更新时间；
- 数据来源；
- 过滤条件；
- 去重规则；
- 负责人；
- 最近变更记录。

---

### 8.2 数据状态提示

页面应展示：

- 数据更新时间；
- 数据是否延迟；
- 数据是否完整；
- 是否存在质量异常；
- 是否为实时数据；
- 是否为 T+1 数据；
- 是否为预测数据；
- 是否为人工修正数据。

---

### 8.3 数据质量提示

如果数据质量异常，应提示：

- 异常字段；
- 影响指标；
- 影响时间范围；
- 影响程度；
- 是否建议暂停使用；
- 责任 owner；
- 修复状态。

---

### 8.4 预测数据标识

如果看板中包含预测结果，必须明确标识：

- 预测值；
- 实际值；
- 预测区间；
- 预测模型；
- 预测时间；
- 回测误差；
- 不确定性说明。

不得把预测数据和历史事实混在一起展示而不标注。

## 步骤 9：视觉设计规范

### 9.1 信息层级

视觉层级应服务业务优先级：

1. 最重要指标最大、最靠前；
2. 异常和风险突出显示；
3. 次要信息弱化；
4. 明细信息放在下方或下钻页；
5. 辅助说明不抢占主视觉。

---

### 9.2 色彩使用

色彩应有含义：

- 绿色：正常、增长、完成；
- 黄色：提醒；
- 橙色：警告；
- 红色：严重异常或高风险；
- 蓝色：信息、趋势、基础状态；
- 灰色：无数据、停用、弱化。

注意：

- 不应使用过多颜色；
- 同一颜色在全系统中含义应一致；
- 不要仅依靠颜色表达状态，应配合文字或图标。

---

### 9.3 数字格式

规范：

- 金额应显示单位；
- 大数应缩写为万、亿；
- 比率保留合理小数；
- 趋势变化显示正负号；
- 空值显示为 “-” 或 “暂无数据”；
- 异常数据应标注说明。

示例：

```text
1,280 万
同比 +12.5%
目标达成率 76.3%
暂无数据
```

---

### 9.4 可读性

要求：

- 字体清晰；
- 行高合理；
- 数字对齐；
- 表格列宽合理；
- 图例清楚；
- 坐标轴不拥挤；
- 标签不过度重叠；
- 移动端避免过密信息。

---

### 9.5 大屏设计注意事项

大屏适合：

- 总览；
- 监控；
- 趋势；
- 地图；
- 预警；
- Top 排名。

大屏不适合：

- 复杂筛选；
- 复杂下钻；
- 大量明细表；
- 长文本分析；
- 精细化操作。

大屏设计原则：

- 一屏讲清当前状态；
- 核心数字足够大；
- 模块不宜过多；
- 动效克制；
- 异常突出；
- 数据更新时间明显。

## 14. 看板验收标准

### 14.1 业务验收

必须确认：

- 是否回答核心业务问题；

- 异常是否突出；
- 是否能支持行动；

必须确认：

- 指标口径正确；
- 数据来源正确；
- 过滤条件正确；
- 去重规则正确；
- 更新时间正确；
- 历史数据一致；
- 与已有报表差异可解释。

---

### 14.3 交互验收

必须确认：

- 筛选可用；
- 下钻可用；
- 联动正确；
- 排序正确；
- 搜索可用；
- 导出正确；
- 权限正确；
- 移动端或大屏展示正常。

---

### 14.4 性能验收

必须确认：

- 页面加载速度；
- 筛选响应速度；
- 大数据量分页；
- 图表渲染性能；
- 并发访问能力；
- 数据刷新稳定性。

## 16. 常见设计陷阱防御清单

| 陷阱 | 表现形式 | 防御方法 |
|---|---|---|
| 图表堆砌 | 页面放很多图，但没有业务主线 | 先定义决策问题和信息层级 |
| 指标过多 | 用户不知道看什么 | 聚焦核心指标，次要信息下钻 |
| 没有口径 | 指标看似清楚，实际各部门理解不同 | 增加指标口径说明 |
| 只看结果 | 只展示销售额，不展示过程指标 | 建立结果、过程、诊断指标体系 |
| 没有对比 | 只有当前值，没有同比、环比、目标 | 增加基线对比 |
| 颜色滥用 | 每个图表颜色不同，无业务含义 | 建立统一颜色语义 |
| 视觉炫技 | 动效复杂但影响阅读 | 以可读性和决策效率优先 |
| 大屏信息过密 | 一屏塞满文字和表格 | 大屏只放总览、趋势和预警 |
| 没有异常提示 | 用户要自己找问题 | 预警和异常置顶 |
| 没有行动入口 | 看完不知道怎么处理 | 增加待办、owner 和处置入口 |
| 没有明细 | 只能看汇总，不能定位对象 | 支持下钻到明细 |
| 权限粗放 | 所有人看到所有数据 | 按角色、组织、字段控制 |
| 导出失控 | 敏感数据可随意导出 | 导出权限和审计 |
| 数据延迟不提示 | 用户误以为是实时数据 | 显示更新时间和数据状态 |
| 预测事实混淆 | 预测值和实际值混在一起 | 明确标注预测和区间 |
| 图表选型错误 | 用饼图展示 20 个分类 | 根据数据关系选择图表 |
| 缺少验收 | 上线后指标不准 | 建立业务、数据、交互验收 |
| 缺少迭代 | 看板上线后无人维护 | 建立访问分析和反馈机制 |
| 无法复盘 | 看板只展示，不记录操作 | 保留历史、导出和处置记录 |
| 缺少移动端适配 | 一线人员无法使用 | 按使用终端设计不同版本 |

## 24. 附加能力：HTML 交互式数据看板生成

当用户的请求包含“生成数据看板”、“转成HTML大屏”、“生成前端页面”等明确的代码生成意图时，除了输出上述设计方案外，你**必须**输出一份可直接运行的静态 HTML 代码。

### 24.1 落地技术栈约束

1. **纯前端单文件**：必须将所有 HTML、CSS、JS 写在同一个 `index.html`（或 Markdown 的 `html` 代码块）中，方便用户复制和在浏览器中直接双击运行。
2. **UI 样式库**：必须通过 CDN 引入 `TailwindCSS`：`<script src="https://cdn.tailwindcss.com"></script>`。
3. **图表库**：必须通过 CDN 引入 `ECharts`：`<script src="https://cdn.jsdelivr.net/npm/echarts@5.5.0/dist/echarts.min.js"></script>`。
4. **图标库（可选）**：可以使用 FontAwesome 或 Lucide 引入 SVG。

### 24.2 视觉与设计美学规范

为了呈现“高级感”和“大屏感”，代码必须遵循以下美学：

- **色彩克制与高级感**：不要使用原色（纯红 #FF0000、纯蓝 #0000FF）。背景优先使用深色暗黑风格（如 `bg-slate-900`）或高级明亮风格（如浅灰背景+纯白卡片）。
- **空间与层次**：充分利用 Tailwind 的阴影 (`shadow-lg`, `shadow-xl`) 和圆角 (`rounded-xl`, `rounded-2xl`)，为卡片和图表容器划分清晰的边界。
- **微交互与质感**：可适当运用玻璃拟态（`backdrop-blur`, `bg-white/10`）、渐变文字或渐变背景（`bg-gradient-to-r`）。
- **响应式布局**：至少通过 Tailwind 的 `grid` 或 `flex` 搭建适合宽屏展示的栅格系统。

### 24.3 交互逻辑实现（核心要求）

**所有交互元素必须编写完整的 JavaScript 逻辑，不可只放 HTML 空壳。** 以下是必须实现的交互清单：

#### 24.3.1 Tab / 标签页切换

如果看板包含多个维度（如"总览"、"渠道分析"、"区域分析"），必须实现完整的 Tab 切换机制：

1. **HTML 结构**：每个 Tab 按钮使用 `data-tab="tabId"` 属性标识，每个内容面板使用对应的 `id="tabId"` 并默认 `display: none`（仅第一个默认 `display: block`）。
2. **切换逻辑**：点击 Tab 按钮时，隐藏所有面板，显示目标面板，并更新按钮的选中样式（如高亮底边、文字变色）。
3. **图表 resize**：Tab 面板从隐藏变为可见后，**必须**对该面板内的所有 ECharts 实例调用 `chart.resize()`，否则图表宽高会塌陷为 0。

参考实现模式：

```javascript
// Tab 切换核心逻辑
function switchTab(tabId) {
    // 1. 隐藏所有面板
    document.querySelectorAll('.tab-panel').forEach(p => p.style.display = 'none');
    // 2. 移除所有按钮高亮
    document.querySelectorAll('.tab-btn').forEach(b => {
        b.classList.remove('border-blue-400', 'text-white');
        b.classList.add('border-transparent', 'text-slate-400');
    });
    // 3. 显示目标面板
    document.getElementById(tabId).style.display = 'block';
    // 4. 高亮目标按钮
    document.querySelector(`[data-tab="${tabId}"]`).classList.add('border-blue-400', 'text-white');
    document.querySelector(`[data-tab="${tabId}"]`).classList.remove('border-transparent', 'text-slate-400');
    // 5. resize 该面板内所有图表
    const charts = tabChartMap[tabId] || [];
    charts.forEach(c => c.resize());
}
```

#### 24.3.2 筛选器 / 过滤条件

如果看板包含下拉筛选（如时间范围、地区、渠道等），**必须实现筛选后数据联动更新**：

1. **数据结构**：将所有原始数据存储在一个全局 JS 变量中（如 `const RAW_DATA = [...]`），方便后续筛选过滤。
2. **筛选逻辑**：当用户修改 `<select>` 或点击筛选按钮时，从 `RAW_DATA` 中过滤出符合条件的子集。
3. **图表更新**：用过滤后的数据重新构建 ECharts 的 `option`，调用 `chart.setOption(newOption)` 刷新图表。
4. **指标卡片更新**：同步更新顶部的核心指标卡片数字（如总量、均值、增长率等）。

参考实现模式：

```javascript
// 全局数据
const RAW_DATA = {
    sales: [
        { month: '1月', region: '华东', channel: '线上', amount: 12000 },
        { month: '1月', region: '华南', channel: '线下', amount: 8500 },
        // ... 所有数据
    ]
};

// 筛选并更新
function applyFilters() {
    const region = document.getElementById('filter-region').value;
    const channel = document.getElementById('filter-channel').value;
    
    let filtered = RAW_DATA.sales;
    if (region !== 'all') filtered = filtered.filter(d => d.region === region);
    if (channel !== 'all') filtered = filtered.filter(d => d.channel === channel);
    
    // 更新指标卡片
    const total = filtered.reduce((s, d) => s + d.amount, 0);
    document.getElementById('metric-total').textContent = total.toLocaleString();
    
    // 更新图表
    salesChart.setOption({
        series: [{ data: aggregateByMonth(filtered) }]
    });
}

// 绑定事件
document.getElementById('filter-region').addEventListener('change', applyFilters);
document.getElementById('filter-channel').addEventListener('change', applyFilters);
```

#### 24.3.3 图表渲染与配置

1. **数据绑定**：仔细读取当前分析报告中的具体数据。将数据硬编码到 ECharts 的 `option` 中，切忌只输出空壳模板。
2. **图表配置优化**：
   - 隐藏 ECharts 默认背景，设置 `backgroundColor: 'transparent'`。
   - 开启 tooltip（`tooltip: { trigger: 'axis' }`）。
   - 调整 legend 样式以匹配深色或浅色主题（如 `legend: { textStyle: { color: '#94a3b8' } }`）。
   - 使用平滑曲线（折线图 `smooth: true`），使用圆角柱状图（`itemStyle: { borderRadius: [4, 4, 0, 0] }`）。
   - 坐标轴标签颜色匹配主题（`axisLabel: { color: '#94a3b8' }`）。
3. **窗口自适应**：监听 `window.onresize`，对所有图表实例调用 `resize()`：
