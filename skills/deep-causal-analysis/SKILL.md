# 深度因果归因与本质探究标准作业程序 (Deep Causal Analysis & Root Cause SOP)

本技能旨在规范智能体如何对复杂系统、客观事件、业务指标或自然/社会现象进行深度的**因果归因与本质推导**。其核心理念是：拒绝用“相关性”或“表面诱因”搪塞，必须建立严密的逻辑因果链与反事实检验。适用于探索客观世界运作规律、进行系统复盘或深度认知构建。

---

## 核心工作流 (Workflow)

当用户需要探究现象背后的“为什么”、“底层机制是什么”或“如何影响最终结果”时，必须遵循以下分析框架。注意：步骤 2 和 3 通常需要交织迭代进行。

### 1. 现象界定与竞争性假设构建 (Phenomenon & Competing Hypotheses)
- **精准界定核心效应 (Define the Effect)**：清晰描述需要解释的终极现象或指标异动。
- **建立竞争性假说 (Competing Hypotheses)**：为该效应提出至少 **3个不同维度的因果假说**。
  * 假说必须尽可能覆盖不同的因果层级（例如：远因/宏观环境 vs 近因/内部机制 vs 触发因素/个体特异性）。
  * *注意：假说的维度必须从具体现象的领域知识中生成，而非机械套用模板。*
- **绘制因果图模型 (DAG / Causal Loop Diagram)**：
  * **必须使用 Mermaid 图表语法** 呈现节点关系。
  * 识别并标记**混杂因子 (Confounders)**（同时影响原因和结果的共同起源）。
  * 警惕并标记**碰撞变量 (Colliders)**（受多个原因共同影响的节点，控制它反而会引入虚假相关）。

### 2. 剥离混杂与因果方向性检验 (Confounding Control & Directionality)
*此阶段旨在穿透表象的相关性，确立真正的因果箭头。*
- **控制混杂因子 (Control for Confounders)**：
  * 必须通过分层分析、控制变量法来剥离第三变量的影响。
- **时间序列与前置性检验 (Temporal Precedence)**：
  * 原因必须发生于结果之前。若同时发生，需寻找天然的外生变量（自然实验等）作为工具变量。
- **排除反向因果与反馈环 (Reverse Causality & Feedback Loops)**：
  * 警惕**正反馈循环 (Positive Feedback Loop)**，界定“初始触发条件”。

### 3. 假设竞赛与机制溯源 (Hypothesis Elimination & Mechanism Tracing)
- **警惕多重因果性 (Equifinality/殊途同归)**：在淘汰假设前，必须思考“这些假设是否并不互斥，而是各自通过完全独立的因果路径导致了同一个结果？”如果是，则不要强行只保留一个，而是承认多条路径同时成立。
- **证据-假设对照矩阵 (Evidence-Hypothesis Matrix)**：
  * 将收集到的事实证据逐一比对，寻找能“杀死”某个假设的确凿证据。必须按以下表格模板输出矩阵：
  | 关键证据/事实 | 假说A (外部冲击) | 假说B (内部突变) | 假说C (结构变化) | 结论/淘汰 |
  | :--- | :--- | :--- | :--- | :--- |
  | [证据描述 1] | 强力支持 (+) | 强烈证伪 (X) | 无关 (O) | 假说B被淘汰 |
  | [证据描述 2] | ... | ... | ... | ... |
- **填补机制“黑盒” (Process Tracing)**：
  * 跨度过大的因果链是不成立的。必须使用定性的**过程追踪法**寻找微观层面的“机制证据”。

### 4. 反事实推理与 INUS 条件评估 (Counterfactuals & INUS Conditions)
- **构建反事实世界 (Counterfactual Reasoning)**：
  * 提出关键问题：“如果当时没有发生变量 X，结果 Y 还会发生吗？”寻找平行历史基准线。
- **评估 INUS 条件与独立贡献**：
  * 大部分原因既非绝对充分，也非绝对必要，而是“一个足以导致结果的复杂条件组合中，不可或缺的那一部分”。区分触发因子（引发雪崩的最后一片雪花）与结构因子（长期积累的积雪结构）。
  * **判定方法**：在想象中去掉该因素，其余条件组合是否仍足以导致相同的结果？如果不能，则该因素是该组合中不可或缺的 INUS 成分。

### 5. 洞察升华与高杠杆节点定位 (Insights & Leverage Points)
- **提炼本质规律 (Extract Core Mechanisms)**：从个案现象中抽象出具有普适性的系统动力学规律或底层逻辑。
- **定位高杠杆节点 (Identify Leverage Points)**：寻找因果网络中“四两拨千斤”的关键枢纽。
- **干预/应对策略（如果适用）**：针对高杠杆节点提出干预措施，拒绝“头痛医头脚痛医脚”。

### 6. 分析边界与局限性声明 (Boundary & Limitation Declaration)
- **必答环节**：必须在最终报告中明确声明以下内容，防止过度自信：
  * **适用范围 (Scope of Validity)**：结论在什么时间、地域、群体或条件下成立？
  * **未观测变量 (Unobserved Variables)**：有哪些潜在的混杂因素可能推翻当前结论，但因数据缺失无法验证？
  * **证据分级 (Evidence Strength)**：当前因果链的哪一个环节是最薄弱的推测？必须按以下标准评定：
    - **强 (Strong)**：有直接经验数据 + 严密的反事实对照支撑。
    - **中 (Moderate)**：有间接数据、类比推理或高度契合的定性观察支撑。
    - **弱 (Weak)**：仅有逻辑上的合理性，尚缺乏实质性经验证据验证。

## 核心设计原则 (Guidelines & Rules)

- 🚨 **相关不等于因果**：看到两个现象同步发生或高度相关时，必须穷尽探讨潜在的共同源头。
- 🚨 **警惕辛普森悖论**：在全量数据中看到的因果方向，可能在细分群体/分层中完全反转。
- 🚨 **无淘汰不推断**：如果没有在分析过程中显式地“证伪”并淘汰掉至少一个竞争假设，说明存在先入为主的偏见。
- 🚨 **防止过度归因 (Over-attribution)**：不要在噪声中强行寻找因果。对于微小的效应量，必须结合统计显著性与常识进行证据强度分级，敢于承认“这可能是随机波动”。

## 常见因果谬误陷阱 (Causal Fallacies & Pitfalls)

| 陷阱/谬误 | 表现形式 | 破解/正确做法 |
| :--- | :--- | :--- |
| **反向因果 (Reverse Causality)** | 误把结果当原因。例如：看到医院死亡率高，得出“去医院容易死”的结论。 | 严格界定事件的时间先后顺序，寻找外生冲击事件。 |
| **忽略混杂因子 (Omitted Variable Bias)** | 发现“冰淇淋销量”与“溺水”高度相关。 | 识别并控制“夏季高温”这个隐藏的共同原因。 |
| **辛普森悖论 (Simpson's Paradox)** | 整体数据看疗法A更好，按病情轻重分层看都是疗法B更好。 | 归因分析必须深入到异质性子群体（Subgroups）。 |
| **幸存者偏差 (Selection Bias / Colliders)** | 研究成功企业的激进特质。 | 纳入“全样本”（包括已消亡的），避免在碰撞变量上产生虚假归因。 |
| **生态谬误 (Ecological Fallacy)** | 观察到富裕国家平均肥胖率高，推断富裕群体更易肥胖。 | 区分“群体级别的因果”与“个体级别的因果”。 |

## 典型工具与方法论决策树 (Methodology Decision Guide)

根据**数据条件**与**探究目标**，选择合适的推断工具：

1. **拥有随机分配的实验对照组 (RCT / A/B Testing)**：
   👉 **金标准**，直接对比干预组与控制组差异，计算平均处理效应 (ATE)。
2. **存在清晰的阈值/规则导致干预发生 (如：考分>60被录取)**：
   👉 使用 **断点回归 (Regression Discontinuity Design, RDD)** 在阈值附近进行局部推断。
3. **拥有干预前后的面板数据 (Panel Data)**：
   👉 使用 **双重差分法 (Difference-in-Differences, DID)** 剥离纯干预效应。
4. **只有干预后的截面观察数据，且是非随机的**：
   👉 使用 **倾向得分匹配 (PSM) / 因果森林** 寻找“长得很像”的对照组。
5. **完全没有结构化数据，属于宏观历史/社会现象探究**：
   👉 使用定性的 **过程追踪法 (Process Tracing)** 收集诊断性证据。
6. **探究系统长期演化、震荡或崩溃的底层机制**：
   👉 使用 **系统动力学 (System Dynamics)** 建模，分析反馈环路与延迟效应。
